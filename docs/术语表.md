# 术语表

> 这套东西内部黑话很多。**不认这些词，你到不了第三步。**
> 按"你会先撞到哪个"排序。

| 词 | 大白话 | 它到底指什么 |
|---|---|---|
| **大脑** | 跟你对话的那个 AI | 你的 DSH 会话。它**不写代码**，只拆活、派活、看结果 |
| **载体** | 干活的 AI 工具 | 独立的 CLI 程序（pi / opencode / codebuddy / qwen-code）。每个角色绑一个 |
| **班组** | 一群 AI 的分工 | 5 个角色：`coder-a` `coder-b` `reviewer` `researcher` `rescue` |
| **卡** | 一张工单 | 一个具体任务：目标、白名单、验收标准、用哪个角色 |
| **派活** | 把卡交给某个载体 | 一条命令，生成任务卡 + 启动对应 CLI + 收回执 |
| **门禁** | 自动测试的总闸 | `门禁.mjs`。跑完全量测试，**机器签字**（不是模型说"我觉得行"） |
| **审核** | 另一个模型复查 | 读门禁摘要 + API 证据，给 pass / reject。与写代码的不是同一个模型 |
| **交付门** | 最后一道闸 | 门禁绿 + 审核 pass + 用户验收，三者齐了才算"能交" |
| **收据** | 干完活的凭证 | `receipt.json`：改了什么、跑了什么、证据在哪 |
| **台账** | 任务清单 | `TASKS.md` + 状态库。每条卡在哪一步、谁在干、卡在哪 |
| **工量账本** | 花了多少 | 每次调用的 token / 时长 / 成本，按角色与卡记 |
| **起飞** | 一切就绪可以开工 | `node doctor.mjs` 说"可起飞" |
| **待裁决** | 需要人拍板的事 | 大脑拿不准时会停下来问你，写进 `待裁决.md` |
| **蓝图** | 项目的施工图 | `PROJECT_BLUEPRINT.md`：模块怎么切、依赖怎么走 |
| **坑库** | 踩过的坑 | 每次踩坑记一条（现象/根因/对策/证据），下次先查它 |
| **一次审核制** | 一个项目只全量审一次 | 不是每张卡都审；整个项目没有待办了才审一次，之后钉住结论 |

## 还有几个名字你会看到

| 名字 | 是什么 |
|---|---|
| `_unattended\` | **程序层**。所有脚本、规则、面板、插件都在这儿。升级只覆盖它 |
| `config\` | **配置层**。唯一允许写绝对路径的地方。**是你的，升级不动** |
| `_crew\` | **数据层**。台账、门禁、运行记录、账本。**是你的，升级不动** |
| `agents\` | 载体 CLI 本体（胖包自带） |
| `setup.mjs` / `doctor.mjs` / `uninstall.mjs` | 装 / 体检 / 卸 |
| `开始.md` | 你唯一要读的东西 |

---

## 一句话记住三层

> **程序层随便升级，配置层你自己改，数据层永远是你的。**
