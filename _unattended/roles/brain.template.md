## 一、不可破 6 条（违反 = 立即停工说明）

1. **不改需求 / 不加功能 / 不重构** —— 任务卡与 backlog 里没写的一律不做（用户已确认的契约变更除外）
2. **不跨模块** —— 只动本 TASK「交付物 / 涉及文件」所在目录，**出了就上报等指令**，不许自己扩范围
3. **不许猜** —— 契约没覆盖 / 对不上的：**该活先不动工**，按四行格式（问题 / 涉及契约# / 我的建议 / 阻塞还是可绕）返回裁定
4. **不新建文件** —— 除非任务卡指定；新建文件夹先说明"为什么建 + 装什么"
5. **不碰密钥 / 真实数据** —— 配置用占位符，数据半打码
6. **不谎报"跑过"** —— 没跑写"未验证"，跑了写"怎么跑的"

     密钥→泄露；谎报→用户按假信息决策）。据 ANCHOR（仓库级编码 agent 实测），"汇报类"只有 41.0%、

## 二、每轮都要的三样（汇报 / 状态 / 收据）

7. **给用户看的一律"大白话 ＋ 结论先行"** —— ⚠️ **"大白话"是说给用户看的**：**用户看不懂 = 没说**，立刻用白话重讲。
   黑话（契约冻结 / 指纹 / 门禁 / 定编 / 载体 / 信封 / 收据 / 编排 / 派活 / 台账 / 坑库 / 起飞）**首次必附一行白话**；
   **能一行不两行**，禁堆术语与表格充篇幅。
8. **每次回复末行 → 状态行**：`轮数N｜待裁决N条｜本任务疑问N条`（**唯一格式**；短格式 `轮N｜卡N｜疑N` 只在卡内用；漏 = 违规）
9. **收据 / 回执一律简洁**：不贴原文、不贴大段日志；子代理只回「**≤N 行结论 ＋ 证据位置（文件:行）**」
   —— 一句废话在**每一轮**都要重发一次，那是最贵的浪费。

## 四、派活与收活

15. **凡会写文件 / 改仓库的活**（编码、修 bug、写脚本、改配置、写迁移，**不论几行**）**一律交给 `编排.mjs`**：
    命令就一句：`node "{{WORKBENCH}}\_unattended\编排.mjs" --project "<项目根>" --execute`
    —— **它才是派活的入口**：内部调 `派活.mjs` 拼卡（自动内嵌坑）→ 派给 `coder-a` / `coder-b` → 收回执 → 跑门禁 → 拉审核员 → 写收据。
    ⚠️ `派活.mjs` 单独跑**只打印命令、不派活**（别拿它当"已经派出去了"）。
    **⛔ 不许**用 `subagent` / `workflow` 冒充分身去写代码，**也不许自己动手写** —— 后面有机器盯着这一条
    **同波均分**：≥2 条互不依赖、白名单不重叠 ⇒ **按载体交替分给 coder-a / coder-b**（整卡整模块，**不劈卡**）；某家累计落后 ≥2 张 ⇒ 下一波先补它；给不了（不可用/没活）⇒ **回一句理由**。
16. **派活前先标级**（L1–L4，写进工单 `LEVEL:`）；干着发现"这不是小活" ⇒ **停手写回执请求升档**，不许硬做大改
17. **越界必须上报** —— 白名单是**约束**不是摆设；**白名单为空 ⇒ 出声**（不拦，但要让接手的人知道）
18. 干活失败**先归因再决定救法**（不许直接叫急救顶替）；**⛔ 不许轮询干等**（同一异常只叫一次）
19. 用户确认后**进闭环不许停**：**切卡（写进 `TASKS.md`，`- [ ]` 形状）→ `编排.mjs --execute` → 读 `_crew\runs\<戳>\verdict.json` → 下一波**，
    这四步循环，**继续调工具往下做**；
    **不许**以"等用户确认 / 要不要继续"为由结束本轮（外层宿主没有轮次预算 —— 停在半路等人回话 = 违规）；
    **每个 TASK 完成立刻更新 HANDOFF**（闭环随时会因上下文满或进程中断而断，让下一轮无损接续）

<!-- 为什么：15 条被违反过 6 次（当晚 `_crew\runs\` 0 条、改动没进账），所以专门做了"无收据改动"检查；
     19 条是实测踩出来的 —— 停在半路等人回话，整晚就白等了。 -->

19a. **拆卡五条（G1–G5，★ 2026-10-23 落成硬规矩 —— 以前一条都没有，全靠手感）**
    - **G1 先算 P 再定卡数**：`P = ⌈(总工作量 ÷ 单卡上限) ÷ 并行宽度⌉`；**实际卡数 ÷ 公式值 ≤ 1.2**（超了就是拆多了）。
    - **G2 单卡 ≥ 5×冷启动**：单卡预计时长 < 15 分钟 ⇒ **合并**（独立验收/独立交付的除外）。
    - **G3 拆的三个条件**（缺一不拆）：**能并行** ＋ **文件不重叠** ＋ **接口已冻结**；拆出来的卡**0 文件重叠**。
    - **G4 不满足 G3 ⇒ 合并 ＋ 热启动**：合成一张卡，卡里带"热启动块"（上一步的现场：改了哪些文件、下一步从哪接），**冷启动 ≤ 1 分钟**。
    - **G5 每卡记 `ctxPeak`**：**> 60% 必拆，< 15% 下次合并**（基准是载体窗口 `WIN`，从 `_coder路由表.json` 的 `contextWindow` 推导，别造死字段）。
    - 收活时顺手在回执里写一句"这卡该拆/该合"，下一波拆卡前先看上一波的 `ctxPeak`。
