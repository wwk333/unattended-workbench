### §2.6 AC 写成"机器能跑的"（2026-10-21 通用化，**硬要求**）

> 背景：AC 原来只有"反引号 + 箭头"一种写法被机器认；实测全盘 75 份收据里只有 **12 份**真让机器跑过验收，
> 其余全是"写着中文、机器没跑、也放行了"。chaojimaliao 首跑就因此漏了一条真缺陷（T1-03 验收红、任务照样 done）。

| 写法 | 机器认不认 | 例子 |
|---|---|---|
| ✅ 反引号 + 期望 | 认 | `` `npm run test -- --run a.test.ts` => passed `` |
| ✅ 反引号裸命令 | 认（只要求退出码 0） | `` `python -m pytest -q` `` |
| ✅ **裸命令**（第一位是已知跑器） | 认 | `python tests\x.py --only T1-03 退出码0` |
| ❌ 纯中文 | 不认 | `窗口1024x960屏不够自动降1倍` |
| ❌ 命令 + 中文尾巴 | 不认（**故意保守**，宁可不动也不猜） | `npm run test 五条全绿` |

- **已知跑器**：npm/npx/pnpm/yarn/bun/deno/node/tsx/vitest/jest/python/py/pytest/pip/uv/poetry/tox/go/cargo/make/cmake/dotnet/mvn/gradle/java/pwsh/powershell/bash/sh/ruby/php/julia… 加新生态只改 `_验收.mjs` 的 `AC_CMD_HEAD` 一处。
- **一条卡至少一条可执行 AC**；`台账.mjs ac --project <P> --id <ID>` 就是它的跑法（机器签字）。
- **交付可以写目录**：`src/render/` 或 `assets/**` ⇒ 该目录下全部算这张卡的（省得逐个数文件，也少一堆假越界）。
- 想让"没可执行 AC"**直接拦住**（而不是放行+标注）：项目根放 `gate.json`，写 `"requireAC": true`。

### 29. 跑腿活派给子代理，只把结论拿回来
子代理在**自己的上下文**里干活，**中间步骤不进你的上下文** —— 你只收到结论。这是本项目唯一
"**既少来回、又不损质量**"的手段（DSH 原生 `subagent` / `workflow`）。

**该派出去的活（"看"和"找"）**：翻多个文件/目录找一个事实（"这个接口在哪儿定义、被谁调用"）· 跑一串排查命令并汇总结论 ·
读一批日志 / 收据 / 看板数据，提炼成几条要点 · 联网查资料（`web_search` / `web_fetch`）。

**不该派出去的活（"判断"和"落笔"）**：蓝图 / 契约 / 波次划分、派活、收活判定、集成、改 `进度.md`、写规则
—— 这些是**你的职责**，别人替不了。

**⛔ 写文件的活不许用子代理（2026-10-12 用户拍板 · 硬规矩）**：
**凡会写文件 / 改仓库的活**（编码、修 bug、写脚本、改配置、写迁移）**一律交给 `编排.mjs`**（即上表 §⑤）：
`node "{{WORKBENCH}}\_unattended\编排.mjs" --project "<项目根>" --execute` —— 它内部调 `派活.mjs` 拼卡，再派给 `coder-a` / `coder-b`；
`派活.mjs` 单独跑**只打印要执行的命令、不派活**。
**不许**用 `subagent` / `workflow` 代替。**派出去之前必答一句**：**"这活会不会写文件？"** 会 ⇒ 它不是跑腿活，回 §⑤ 走 `编排.mjs --execute`。

为什么写死（**实测，不是假想**）：2026-10-12 你把三个编码任务（T52/T53/T54）派给了 DSH 原生 `subagent`，
prompt 里还让它自称"编程班组（coder-a）" ⇒ 结果这活**没有任务卡、没有回执、没有信封、没有门禁、没有审核**
（项目 `_crew\tasks\` 里一张 T5x 的卡都没有，`runs\` 最新批次停在 10-07），而台账里照样被标成 `[x] done`
⇒ 账本、看板、审核三样全对不上。**"派给了自称 coder 的子会话" ≠ "派活给班组"**：班组的活要落卡（`_crew\tasks\<ID>.dispatch.json`）、
要有回执与信封、要过门禁、要留账本。
⚠️ **机器侧也有一道门**（2026-10-12 加）：`台账.mjs set --status done` 若**找不到派活回执**会**拒收**
（确实不是派活干出来的活，带理由 `--no-receipt "…"` 才放行、且留痕）。撞上这道门不是让你去绕它，是让你回去走 §⑤。

## §5 长命资源：不许在会话里直接起（原 §30）

## ★ 2026-10-16 新增一条硬规矩（长命资源：不许在会话里直接起）

### 30. 起"该活过这一轮"的进程，一律走「确保」脚本；起完必须登记

**什么算长命资源**：任何**听得见端口**的东西（后端 / dev server / 代理 / 网关 / 工具服务 / 面板），以及看守与看护循环 ——
一句话：**该活过当前会话的进程**。

**为什么写死（实况，不是推演）**：2026-10-13 有人在会话里起了 `npm run dev`（`某个项目根`，听 3000），
换新会话后它**还在跑**（DSH 右上角"1 个后台任务运行中 · 48 分 5 秒"），而**新会话看不见它、也停不掉它** ——
没人知道它是谁的。根因不是哪个软件的 bug，是**这些进程的归属挂在了"会话"上，而会话是短暂的**。

**怎么做（三条，缺一不可）**：
1. ⛔ **不许在会话里直接敲** `npm run dev` / `node xxx` 这类命令。那样它归**这条会话**，换会话即成孤儿。
2. ✅ 走现成的"确保"脚本（**detached ＋ 无窗口 ＋ 探活 ＋ 登记**一条龙，幂等、跑几次都行）：
   `确保工具服务.mjs`（19400）· `确保路由.mjs`（19420）· `确保看守.mjs`（换会话看守 ＋ 看护循环）·
   后端/dev server 用 **`确保后端.mjs --project <项目> --port <端口> --cmd "<命令>"`**
   （不写 `--owner` 时，归属＝**发起它的那个会话**；写 `--owner 工作台` ＝ 永不交接）。
3. ✅ **起完必须登记**（上面这些脚本已经替你做）。登记册＝`_crew\服务登记.json`，
   **唯一写入口**是 `_unattended\登记服务.mjs` —— 别处要登记/下架**一律调它的 `up()` / `down()`**，
   ⛔ **不许自己写那个文件**（各写各的＝口径必然分叉）。

**怎么看、怎么判**：看板顶部那颗「**长命资源 ●**」（绿＝登记与现实一致 / **黄＝有孤儿或端口属主不符，悬停里点名** / 红＝登记为"该活着"的死了）；
命令行 `node _unattended\登记服务.mjs verify`（exit 0=绿 / 2=黄 / 3=红）；
**要"那一份结论"就跑 `node _unattended\长命资源巡检.mjs`**（★ b91：跑一次就退的小工具，**`_crew\长命资源状态.json` 的唯一写方**；
`--force` 立刻真核 / 默认 30 分钟内刚核过就沿用并标"几分钟前的"）；**看护不再每趟核** —— 它只读那份纸，
超过 30 分钟才顺手叫一次巡检（它那趟因此从 ~730ms 回到 ~40ms，"发现卡死/叫醒大脑"**一字未改**）。
谁在动服务（起/停长命资源、换会话交接、面板起网关）**谁就顺手叫一声**（实现在 `_unattended\_叫巡检.mjs`）⇒ 结论**当场新**。

**⚠️ 两条纪律**：① **看护与面板都不擅自杀谁** —— 要停谁用 `登记服务.mjs down --name <名>`（或换会话交接时点名 `--handover-stop`）；**孤儿只报告**，查清是谁的再决定"登记它"还是"停掉它"。② **黄灯不是"坏了"**：孤儿常常是别人起的开发服务器，别急着杀。

**换会话时**：`换新会话.mjs` 会自动把 `owner=旧会话` 的长命资源**接管**给新会话（**要停的必须点名**），留痕在 `_crew\换会话交接.json`；
判据＝**交接后不存在 `owner=旧会话` 且还该跑着的项**。
**并且**：交接单里还会记一段 `wrap`（**旧会话到底收尾了没有**，判据在 `_unattended\交接核验.mjs`；⛔ 归档会话会被宿主
判 `blocked`、收尾必然落空）——看板「🔁 最近一次换会话」那块与体检的「交接」一行读的就是它；**不是 ok 就看护会留告警**（b91）。

## §6 任务分级 L1–L4：派活前必须先标级（原 §31 之一）

## ★ 2026-10-16 新增一条硬规矩（任务分级 L1–L4：**派活前必须先标级**）

### 31. 每张卡开工前**先标一个级**，写进工单 `LEVEL: L1..L4`

**为什么写死**：二档（quick/deep）逼着人做"非小即大"的判断，**中间态无处安放** —— 而"单模块写代码"这类活
占了日常的绝大多数（用户 2026-10-16 原话："一个任务不应该只有 quick 和 deep，有的时候处于中间态"）。
标级不是形式：它**同时决定**四件事 —— **用哪档模型 · 步数预算 · 验证强度 · 卡片形态**。

**一分钟判别（按顺序问，命中即停；拿不准就往上一级取）**：

1. 只是把**已有的某个值/文案/断言换掉**、不新增判断？→ **L1 小改**（形态 slim）
2. 只在**一个模块内**加/改逻辑？→ **L2 写代码**（**默认就在这一级**）
3. **跨模块** 或 **要先复现定位**（真机/日志/多轮排查） 或 **改 DTO/字段口径**？→ **L3**
4. **接新依赖 / 改契约·蓝图 / 动库结构**？→ **L4**

> **级别看"这张卡自己要干的活"，不看"这个 bug 当初怎么发现的"**：真凶是在真机上才暴露的那是**诊断**；
> 派出去的卡若只是"按已定位根因改一处、单文件无新分支" ⇒ 那张卡仍是 **L2**。

**落到哪（三件事，全自动，你不用管）**：

| 级 | 模型 | 门禁 scope | 拉不拉审核员 | 卡片形态 |
|---|---|---|---|---|
| L1 | 看板配的 L1 档 | **不单跑门禁**（只跑卡里那条可执行 AC） | ❌ | **slim**（目标原文＋改法＋1 条命令＋白名单） |
| L2 | 看板配的 L2 档 | `门禁 --quick`（构建＋全仓单测） | ❌ | std |
| L3 | 看板配的 L3 档 | **全量门禁** | ✅ | std |
| L4 | 看板配的 L4 档 | 全量 ＋ 波及分析 | ✅ | full |

**四条纪律**：
1. **一个数一个包**：默认只写 `L2`；真要单独调某一项才写覆盖（例：`L2+full` ＝ 按 L2 的模型跑、但要全量门禁）。
2. ⛔ **任何模型名都不许写进代码/文档** —— 每级用什么模型**只由用户在看板里定**，落在 `_crew\agents.json`；
   **某级没配 ⇒ 派活当场报错**（`resolveRole()` 的 fail-closed），**绝不静默走默认档**。
3. **可中途升降级**：L1/L2 干着发现"这不是小活" ⇒ **停手写回执请求升档**（不许硬做大改）；L4 干着发现"其实一行" ⇒ 可报"建议降级"。
4. **额度兜底不越级**：兜底链的硬规矩是"只换 API、不换模型" ⇒ **级不会被兜底悄悄改写**（保留）；
   但每级模型要挑**额度稳**的家，否则小事也会卡住等人。
5. **思考档位是三档抽象、不是具体值**：看板上你只选 **省 / 中 / 狠**，写在 `levels.<级>.effortTier`；
   落地时按 **DSH 的真实规则**算"这个模型支持哪些档"——**标准五档 `off/minimal/low/medium/high` 对推理模型默认就有**，
   只有 **`xhigh` / `max` 需要显式声明**（所以 xiaomi 的 MiMo 只到 `high`，没有 `max`），再从该档候选里取第一个支持的。
   **取不到首选就如实降级**（例：xiaomi 上「狠」→`high`，收据里写清）；模型查不到 ⇒ 不传、记"未核实"。
   ⛔ **起飞前检查 ①c（`_档位对账.mjs`）是硬闸**：某级一个候选都不在支持集合里 ⇒ **不许起飞**
   （那正是"你要 max、实际被静默夹到 high"的静默）。档位候选串在 `agents.json` 的 `levels.effortTiers`。

**怎么被机器验证**（不用你操心，但要知道它真会发生）：门禁 scope 与"拉不拉审核员"由**本波最深一级**决定
（读派活收据的 `level`）；账本与看板都记级号（防"看板显示 max 档、实际跑的是 L1"）。
逃生口：**L1/L2 只跳过审核员，门禁照跑**（L1 只跑卡里的可执行 AC）；确要连审核员也拉起来，加 `--force-review`。

**依据**：KB `重构\任务分级-施工文档.md`（§2 判别法 / §3 四维度 / §5 L2 的三条护栏）。
