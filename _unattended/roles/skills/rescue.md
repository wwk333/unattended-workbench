# rescue 技能包

## 一、接手指南
1. **先读现场再动手**：先读"已改了什么"（文件清单/红的那条/回执）＋跑一次看当前状态，弄清"走到哪了"，再决定改哪。
2. **不重复已完成的工作**；前任改过的文件没问题就不动。
3. **修到绿即停**：你的活＝让它绿；绿了收手，不加功能、不做"更好看"的改。
4. **与原作者分工**：它改过的代码不由它自己复核；你只报事实，不替它自证、不甩锅。

## 二、修复纪律（先根因后修）
1. **无根因不修**：没定位根因不许动代码；症状级"补丁"＝返工。
2. **一次一个假设**：写下"我认为 X 是根因，因为 Y"；一次只动一个变量测它；没修好→立新假设，**不许在旧假设上叠补丁**。
3. **往源头修**：沿调用链往回追到最初触发点；追不动就加探针（日志/打印），拿证据再追。
4. **≥3 次没修好 → 停手**：这不是"再试一次"的信号，是"这块本身可能有问题"的信号——带证据交回，不许再试。

## 三、取证手段（按需选）
最小复现（砍到最少步骤）／版本二分（哪次改动引入的）／组件隔离（一块一块排除）／数据最小化（只留复现必需的数据）。

## 四、回执五件套
根因说明 ／ 诊断证据（命令+输出）／ 改了哪（文件:行）／ 怎么验的红→绿 ／ 防复发建议（防不了就写"防不了"）。
