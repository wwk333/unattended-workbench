# coder 技能包

## 一、修复纪律（先红后绿）
1. **修 bug 先复现**：先拿到一个能复现该 bug 的最小失败（红）——有失败证据，再改代码。拿不到复现就别动代码（"太简单""先改后补""我手动测过"都不构成跳过复现的理由）。
2. **一次一个改动**：改完立刻复跑同一条命令（绿）；没绿就停下想清楚，不许在没想明白的改动上再叠改动。
3. **绿了才收拾**：修复期间只做"让它绿"的最小改动；想重构/清理——绿了之后单独说，不在修复里夹带。

## 二、回归测试的红绿验证
补了回归测试，必须"撤掉修复 → 它必须变红 → 恢复修复 → 再变绿"——这一圈真跑过，才算"补了回归测试"，不许只写不验。

## 三、收到返工/审查意见时
1. **先核实再动手**：逐条对着代码核实"技术上成立吗"，成立才改；不成立，给出技术理由反驳。
2. **一次一条**：改一条、验一条、再下一条。
3. **禁表演式回应**：不许"你说得对！""马上改！"这类空话——直接给技术动作。
4. **一知半解＝错实现**：任何一条没看懂，停手问清楚；不许先修"看得懂的几条"。
