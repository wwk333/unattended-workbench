## 自启（随 DSH）

- **谁拉**：`_unattended\bridge-plugin\lib\index.js`（插件 `dsh-crew-bridge`）在 `apply()` 里调 `ensurePanel()`。
- **怎么判**：**HTTP 探活** `/health`（不用"读进程命令行"这种散文判据）；
  活着就**不重复起**（绝不 spawn 第二个 —— 端口会打架、日志会互相覆盖）。
- **起不来怎么办**：**只告警一行**，绝不影响 DSH 与换会话桥；看 `panel.out.log`。
- **语义**：面板与 DSH **同生共死** —— DSH 关了它就没意义，下次开 DSH 再起。
- **可覆盖**：`DSH_PANEL_PORT`（默认 19450）· `DSH_PANEL_SERVICE`（默认本目录 `service.mjs`）。
- ⚠️ 改了插件代码**要重启 DSH** 才生效（宿主读的是启动时那份代码）。

## 它怎么做到"和旧看板一个口径"

两个地方**共用同一份代码**（不是各写一份）：

```
_unattended\面板\core.js                      ← 逻辑核心的源（人改这一份）
        │  由 _probe\panel-b1\_patch-core2.mjs 内联进 ↓
        ▼
_unattended\sidebar-plugin\lib\client.js      ← 旧看板（DSH 右侧栏）＋ 标记区
        // ══ CORE-BEGIN:
        …与 core.js 逐字节相同…
        // ══ CORE-END:
        ▲
        │  服务端启动时把标记区抠出来，与 core.js 逐字节比对
        │  不一致 ⇒ **拒绝启动**（宁可不开，也不许两边显示不同的口径）
        │  页面用 <script src="/core.js"> 拿同一段
_unattended\面板\service.mjs + index.html + 页面.js + 页面.css
```

**为什么用"内联 + 标记区"而不是 `import`**：实测宿主加载 client bundle 用的是
**同源外部经典脚本**（`dsh-client-modules/lib/client.js:451`，`createElement("script")` + `src`），
**不是 ESM** ⇒ 共享代码只能是经典脚本，不能用 `import`。

**改逻辑的正确姿势**：只改 `core.js`，然后重跑 `node _probe\panel-b1\_patch-core2.mjs`
（它每次都从基版 rebuild，**幂等**；自带"标记区 == core.js"自校）。

## 边界（批 1 如实记录）

1. **没有会话上下文**：旧看板跟"当前会话工作区"；面板是独立页 ⇒ 跟 `_crew\当前项目.txt`
   那个钉子（或在地址后面加 `?project=<盘符>\...\某项目`）。**没钉就明确说"没钉"**，不猜。
2. **渲染层是两套**（旧看板 React / 面板原生 DOM），但**口径与文字都在 core.js 里**，
   表格行由 core 的 `crewCells` / `providerCells` 生成 ⇒ 数字和文案不会漂。
   唯一（有意）例外：**「⚙️ API 额度」区的模型搜索打分** —— 旧看板里那份是 `QuotaPanel` 内的局部
   `mScore`，面板用 core 的 `modelScore`（同一套规则：去符号/跳字母≤2/词序随意），批 2 逐项核对。
3. **换会话桥不在这里**（19390 那条）—— 已在**批 3**搬进无界面插件 `dsh-crew-bridge`
   （旧看板已撤并归档；`换家后验证.mjs` 全合格）。
4. **`/run`（跑一轮）与旧看板同一条路**：spawn `编排.mjs --project <项目> --execute`，
   日志落 `<项目>\_crew\panel-run.log`，输出**不接管道**。锁名 = `<项目>\_crew\crew.lock`。
5. **写操作复用**：钥匙/模型/优先级/检测直接调 `额度面板.mjs` 的 `handle()`（与命令行同一件事），
   面板没重写一套。
6. **只监听 127.0.0.1**，不要改成 0.0.0.0（那会把改钥匙的口子开到整个局域网）。
7. **「看」的实时性**：帧数据＝读现成的 board-data / ledger / 信封（5 秒缓存）；翻译器认不出的行**跳过**。
   "每一步实时滚"依赖编排**「边跑边写」**（2026-10-10 已做）——但**数组族载体**（CodeBuddy / Qwen）
   输出要等跑完才是整段 JSON，运行中看不到中间（JSONL 族 Pi / OpenCode / CodeWhale 可逐步看）。
8. **「控」的边界**：暂停＝真杀＋双轨收据（项目级 `frame-actions.jsonl` ＋ 面板级 `panel-actions.jsonl`）；
   **继续/插话＝"照真配置拼出续跑命令"的预览**（★ 2026-10-10：逐家 resume 旗标已实测并写进 `agents.json` 的 `sessionFlag`，
   预览里给的就是真命令：模型／档位／`--session`／`--resume` 都齐，会话号取自账本 `calls[].sessionId`）——
   **但不执行**（不 spawn、不杀）；真执行待首次真项目解锁。**续不了就如实报错**（如 DSH headless 没有续跑口、账本没记会话号），**不拼假命令**。
   ★ **会话在盘上核对**（b4）：Pi 会先看那个会话号**在不在** `~/.pi/agent/sessions\`（老账本记录是 `--no-session` 时代的、盘上没有）
   ⇒ 不在就**直接报"盘上找不到"**，不给一条注定被载体拒绝的命令；其余载体如实标"未接核对"（`null`，**不假装知道**）。
   编排侧"识别人工暂停、不自动重试"**未做**（有项目时再对）。
