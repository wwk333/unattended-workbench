## 一句话

把**换会话桥（127.0.0.1:19390）**和**看护拉手**从旧看板插件里搬到新的**无界面插件** `dsh-crew-bridge`，
然后**同一次重启**里"新插件上、旧看板插件撤"——右侧栏那个「班组看板」标签页随之消失（页面功能已在 19450 面板上）。

## 为什么必须"一次重启里同时换"（不能先上后撤）

`19390` 同一时刻**只能有一个监听者**。所以：

```
DSH 重启前                  DSH 重启后（一次完成）
─────────────────          ────────────────────────────────
dsh-board-sidebar          dsh-crew-bridge      ← 桥上（19390）
 ├ 桥 19390  ← 主人在此      └ 桥 19390          ← 新主人
 └（顺带拉起看守）           （顺带拉起看守 —— 同样幂等）
```

⚠️ **桥不能停**：它是"换会话"的唯一通道（`换新会话.mjs` / `swap-entry.mjs` / `进度看护.mjs` /
`看板数据.mjs` / `_重启后验证.mjs` 都靠它）。所以换家时**先保证新插件在 bundles 里**（脚本一次改完），
再重启 —— 中间不存在"两边都没有桥"的窗口。

## 要改的三处（都已脚本化：`_unattended\换家.mjs`）

| # | 改什么 | 现况 | 改成 |
|---|---|---|---|
| ① | `<profile>\package.json` 的 `dependencies` | 无 | `"dsh-crew-bridge": "file:<DSH根>\无人值守\_unattended\bridge-plugin"` |
| ② | 同文件 `dsh.profile.bundles` | 含 `dsh-board-sidebar` | 去掉 `dsh-board-sidebar`、末尾加 `dsh-crew-bridge` |

`<profile>` = `<用户目录>\.dsh\profiles\desktop`

改前 `换家.mjs` 会把 `package.json` 逐字节备份到 `<profile>\_backup-batch3-<时间戳>\`。

## 操作序列（挑一个你没在跑活的时刻）

**推荐走"两阶段"**（更稳：每一步都能单独看结果，任何一步不对劲都可以立刻回滚）：

```powershell
# ── 阶段 A：先把旧看板插件摘掉（右侧栏解放）──
node _unattended\换家.mjs --retire            # 先看要改什么（不落盘）
node _unattended\换家.mjs --retire --apply    # 真改（只动 bundles：去掉 dsh-board-sidebar）
#   → 重启 DSH
#   → 预期：右侧栏「班组看板」标签页消失；⚠️ 19390 暂时没人监听（**这是预期的中间态**）

# ── 阶段 B：让新桥插件上岗（把 19390 接回来）──
node _unattended\换家.mjs --install --dry     # 先看要改什么
node _unattended\换家.mjs --install --apply   # 真改（加依赖 ＋ bundles ＋ junction）
#   → 重启 DSH
#   → 跑 node _unattended\换家后验证.mjs  ← **一条命令看全部结果**
```

> **为什么建议分两步**：新桥插件是**新代码**（虽然已在假宿主里 25/25 验过）。
> 分两步时，万一它加载不了，你只是"桥暂时不通"，**不会**同时失去"旧看板还在不在"这个对照。
> 想省一次重启，也可以用 `--apply`（一步到位：摘旧 ＋ 上新）；但那要求对新插件有把握。

**阶段 B 之前**（也就是阶段 A 之后、19390 空着的那段时间）：换会话相关脚本会连不上桥 ——
这是**预期的**，别在那时跑 `换新会话.mjs`。

## 怎么退（一条命令）

```powershell
node _unattended\换家.mjs --rollback      # 还原 package.json ＋ 删掉新 junction
# 然后重启 DSH：旧看板插件照旧加载，桥仍由它提供
```

回滚**不动**旧插件目录（它一直都在，只是被从 bundles 里摘了）——所以回退是"加回去"而不是"重装"。
