# 项目剖析文档（Project Anatomy）

**它是什么**：不是"介绍项目"的文档，是把项目**剖开摊平**——一处一页，页首人话讲清它是什么、干什么、花了什么，页内原封不动放着它本身。读者是不懂代码的人，他凭直觉找问题、下判断、做优化。
**一条铁律**：**唯一依据是实机现状**（文件真内容 / 配置真值 / 真跑出来的输出 / 时间戳）。文档只当线索，对不上就写实机，并把这条差异记进疑点。

## 分工（这条决定成败）

| 谁 | 干什么 |
|---|---|
| **AI** | 只写「人话」：六问 + 疑点。**绝不手抄原文、绝不填机器字段**（填了就是编数字） |
| **脚本** | 灌原文、回填 `规模/指纹/抓取`、报「未灌 / 过期 / 孤儿 / 缺标记」 |
| **用户** | 看、批注、决定改什么；他写进「我的批注」区的内容永远不许覆盖 |

## 产物：一本册子

- 册子目录固定叫 `项目剖析`，放在库里该项目的文档夹下。**工具靠这个名字找它，不许改名。**
- 首页 `00-总目录.md`：frontmatter 只有 `项目根: <项目目录>`——**换项目只改这一行**。首页由脚本生成，别手写索引。
- 其余**一物一页**：页名 = `类别·能唯一区分的最短路径（人话后缀）`，类别 ∈ 规则 / 配置 / 脚本 / 界面 / 文档 / 数据。
  - **同名文件必须带上级目录消歧**（`脚本·adapters·pi.mjs（…）` 与 `脚本·会话carriers·pi.mjs（…）` 是两页）。
  - 总纲页 / 机制页 / 目录说明页**不写 `源文件` 字段**（它们不是一个文件）——脚本见到没有该字段的页会跳过，正好。
- 每页骨架见 [`references/页面骨架.md`](references/页面骨架.md)。

## 六问（每页固定；人话、禁形容词、能一行不两行）

1 **这是什么** → 2 **干什么用**（什么时候起作用、什么时候其实不会跑）→ 3 **谁在用它** → 4 **花了什么** → 5 **为什么这么做** → 6 **疑点（现状可证）**

- 「谁在用它」**必须 grep 出来**（范围限活文件，排除 `backup\`、`history*\`、`*.bak*`）；没人用就写"没有任何地方在引用它"。
- 「花了什么」只写能核到的（行数、是否零 token、跑一次的代价）；拿不到就写"未核实"，**不许估**。
- 「为什么这么做」挖不到就写"没找到理由"，**禁止替它编**。
- 「疑点」只写六类**现状可证**的：断链 / 死物 / 重复 / 矛盾 / 过期 / 空转。每条带 `文件:行` 或来源标记；**没出处的宁可不写**。这一条是整本册子的价值所在。

## 来源标记（全册统一）

①实机（文件:行 / 实测输出 / 时间戳）· ②坑库或历史备份 · ③仅文档说法（未证实）

## 流程

1. **定两个路径**：`<项目目录>`、`<库路径>`。库根以 `obsidian.json` 里 `open:true` 的那个为准，**别信文档里写的路径**。
2. **清点活文件**：脚本 / 配置 / 规则 / 界面 / 文档 / 数据；排除 `backup/`、`history*/`、`node_modules/`、`*.bak*`、纯日志。
3. **先交样张**：首页 + 3 条（挑最长和最核心的），等用户确认格式再铺开——格式不对只返工 3 页。
4. **分块派写**：一个写手包 6 个文件、并发压到 4；每块都发同一份「页面骨架 + 六问 + 铁律 + 2~4 页样板」。写手开工前先 `obsidian_list` 看已有页名，**已存在就跳过**（并行时这是硬要求）。
5. **两页收尾**：
   - `整体怎么转`（总纲）：由哪几块组成、任务/数据怎么流、谁是大脑谁是手、**钱和上下文从哪漏**、哪些必须人拍板、现在卡在哪。
   - `疑点总表`：把各页疑点合并同类项，按六类分表，末尾给「最该先动的 N 条」。**合并同一条**，别让同一件事占三行。
6. **跑脚本灌机器区**（下节），跑完再体检一次。
7. **核验**：抽 6 页（各类别都抽到）逐条回原文件对行号；确认机器字段都填上了、代码页没原文区、非代码页有 AUTO 标记。

## 工具（都在 `<skill-directory>/scripts/`）

```text
node <skill-directory>/scripts/剖析.mjs --dry     # 先演练：看它要动哪些页、AUTO 标记认不认得出
node <skill-directory>/scripts/剖析.mjs           # 灌原文 + 回填 规模/指纹/抓取（写前自动备份到 .剖析备份\）
node <skill-directory>/scripts/剖析.mjs --check   # 只体检不改：未灌 / 过期 / 孤儿 / 缺标记（exit 1 = 有问题）
node <skill-directory>/scripts/重排首页.mjs       # 按真实文件列表重排 00-总目录（页数永不手数）
node <skill-directory>/scripts/切提示词.mjs       # 提示词正本改过之后：重切 references\生成提示词.md
```

- Windows 上也可以**双击** `scripts\剖析.cmd` / `剖析-体检.cmd` / `重排首页.cmd`。
- 库根不传 `--vault` 时默认 `{{知识库}}`（可用环境变量 `DSH_KNOWLEDGE_VAULT` 覆盖）。
- 脚本**只动** AUTO 区与那三个 frontmatter 字段，**绝不碰**人话区与「我的批注」区；疑似含密钥的源文件（路径含 `secrets`/`key`/`token`/`密钥`）默认不灌原文。

## 踩过的坑（照做能省一晚上）

- **先 `--dry` 再真跑**：本 skill 第一次实跑就是靠演练发现"一个 AUTO 标记都没匹配上"（正则少写了 `--`）。
- **绝不让 AI 抄原文**：手抄必然漂移，而且读者再也分不清"是它本来的样子，还是 AI 改过的"。原文一律脚本灌。
- **`.cmd` 写成单行 + 判定打在 stdout**：`write` 工具落下来的批处理是 LF 行尾，**多行**会在 cmd 下报 `'-xxx' is not recognized` 且行为不定；**单行与行尾无关**（已实测：LF 单行能跑通）。
  但**别指望 `.cmd` 的退出码**——链尾的 `pause` 会把脚本的 `1` 吃掉、永远返回 0（实测）。双击的人只看得见屏幕，所以**脚本必须把「判定」打在 stdout**，否则他会读成"全一致"（假绿灯）。
- **"glob 拿不到" ≠ "东西不存在"**：`dir/*` 只匹配**直接子文件**，目录里只有子目录时会报"没有文件"。判存在性要把深度写清楚，或直接用 `**/*`。
- **受限沙箱里 shell 全挂（`0xC0000142`）**：那不是环境坏，是一层沙箱把进程初始化掐了——**同一条命令换完整权限再跑一次**通常立刻正常。
- **页数别手数**：数错一次（140 / 145 / 150）就是首页全错；交给 `重排首页.mjs`。
- **别写"我猜"**：册子里每一个数字都要有出处。宁可留"未核实"。
