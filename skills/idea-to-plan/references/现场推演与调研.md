# 现场推演与调研（**推演＝去查，不是查表**）

> 一句话：**"提前推演"不是我照着一张表念，而是我拿他的策划，现场去查"这东西真做起来，路上还缺什么"。**
> ⚠️ 这类东西（资质／备案／平台要求／费率／审核口径）**一年一变**。写死在 skill 里＝教人按去年的话办事。
> 所以本文件**只放方法**：查什么、怎么查、查到怎么记、查不到怎么说。**答案每次现查，查完落进这个项目的调研库。**

## 1. 先从他方案里抠出"外部依赖点"

推演的原材料是**他已经说过的那些话**，不是我凭空想。逐句过一遍，凡是不能靠写代码搞定的，都是"外部依赖点"：

| 他说的 | 抠出来的外部依赖点 |
|---|---|
| "做成手机 App" | 应用市场、软著、隐私政策、开发者账号 |
| "别人也能用" | 账号体系、数据归属、隐私、可能要备案 |
| "要收钱" | 收款资质（营业执照／商户号）、发票 |
| "用 AI 写／对话" | AI 接口的 key 与额度、内容合规 |
| "上网上" | 域名、备案、证书、服务器 |
| "要发短信／发邮件" | 短信签名与模板报备／发信域名 |
| "放用户上传的图片" | 存储、鉴权、内容审核 |
| "给别人看到某些数据" | 权限、可见性、越权风险 |
| "装到电脑上" | 签名证书、杀毒误报、更新通道 |
| "要在微信里打开／分享" | 微信主体、公众号/小程序类目、域名与业务域名 |
| "要自动跑／定时跑" | 一台常开的机器或服务器、日志与告警 |
| "要备份／不能丢" | 备份位置、保留多久、谁来恢复 |
| "要多人同时改" | 并发写、冲突处理、谁有权改 |

抠完之后，**按"要办／要买／要接／要等"分四堆**（这四个字比"资质/合规"更好懂，也好让我自己不漏）。

## 2. 每个依赖点必须查清 5 件事（缺一件不算查过）

| # | 要查清 | 为什么 |
|---|---|---|
| 1 | **现在的要求是什么**（不是去年） | 政策一年一变 |
| 2 | **谁去办**（他本人／代办／我） | 决定它进"人工活"还是"代码活" |
| 3 | **大概多久** | 决定它要不要排在第一批之前 |
| 4 | **查到的费用**（能免就说免；查不到写"未查证"，**不许估**） | 决定要不要换方案 |
| 5 | **最近变过没有**（有没有新规／过渡期） | 最容易踩 |

## 2.1 用户主动问"要花多少钱"怎么办

**不要**把预算做成问题；但他问了，按**查到的事实**回答，并分成三类：

| 类型 | 例子 | 怎么说 |
|---|---|---|
| **一次性人工活** | 软著、备案、上架、开发者账号 | "查到的是 ____（来源+日期）；没查到就说未查证" |
| **每月固定** | 服务器、域名、存储 | "大概每月 ____；查不到就写未查证" |
| **按用量** | AI 接口、短信、云函数 | "按实际用量结算；能查到单价就写单价＋来源，查不到写未查证，**不预估总额**" |

**纪律**：
- 不许拍脑袋说"应该免费/大概 30 天"；数字要么来自查到的页面，要么写"未查证"。
- **不要反问"你预算多少"**——他答不上来，而且预算不该反过来决定需求。
- 如果费用会明显改变方案（比如"上架要几千块"），把它写进方案 §7，并在 §0 提醒一句："这件事可能影响你要不要做 App。"

## 3. 怎么查（三条纪律）

1. **权威源优先**：官方公告／官方文档 ＞ 大平台帮助中心 ＞ 行业文章 ＞ 论坛。**冲突以更靠前的为准**（这条和项目库的权威顺序一致：原始 URL ＞ 资料原文 ＞ 笔记）。
2. **至少两个独立来源**互相对上，才算"查到了"；只有一个来源 ⇒ 写"据 X，未交叉验证"。
3. **每条都记：URL ＋ 抓取日期**。没有日期的结论等于没有结论。

**搜索词模板**（中文优先，因为他的场景在国内）：

```
<平台/事项> 最新 要求 2026          # 例：应用市场 上架 要求 2026
<事项> 官方 办理 指南 site:gov.cn
<事项> 费用 多少
<事项> 新规 变化
<同类产品> 怎么上架 的
```

## 4. 查不到 / 查不准，怎么办（**不许编**）

三种处理，按顺序：
1. **换词再查一次**（同义词、平台名、口语说法）。
2. **查到"找谁问"** —— 这不丢人：写"这个要问 ____（某平台客服／代办／工商），我查到的口径是 ____，但没交叉验证"。
3. **标「未查证」** 进方案，并写清**它会挡住哪一步**（"软著没下来 ⇒ 上架那一步做不了"）。

> ⚠️ 绝对不许做的一件事：**凭印象写"大概要 30 天""应该免费"** —— 数字必须来自查到的页面，否则写"未查证"。

## 5. 查到的，落进这个项目的调研库（**这就是"一次投入永久复用"**）

推演出来的东西**不许只活在对话里**。按场景建抽屉，一个抽屉管一类问题：

```
抽屉示例：上架与合规-App ／ 上架与合规-小程序 ／ 收钱要什么 ／ AI 接口与额度
原文：   资料\<抽屉>\<他查到的那个官方页面，存成 md>
来源：   登记来源.mjs 写（带 URL ＋ 抓取日）
```

```powershell
node {{工作台根}}\_unattended\登记来源.mjs --project <P> --drawer "上架与合规-App" `
     --file "资料/上架与合规-App/应用市场上架要求.md" --type web `
     --url "<官方地址>" --note "软著/隐私政策/开发者账号，查到 2026-10 口径"
node {{工作台根}}\_unattended\调研索引.mjs --project <P>
node {{工作台根}}\_unattended\调研体检.mjs --project <P>
```

**为什么必须落库**：
- 下次同类项目（或者他自己过两个月又想做）→ `查调研.mjs` 一查就有，不用重查一遍；
- 库有 **30 天过期**提醒（`调研体检` 会报），过期了才重查 —— **政策变了有人提醒**，这正是不写死的好处。

## 6. 推演的起手式：六组问题（**只是方向，每组都要去查**）

> 这六组是"别漏维度"的提醒，**不是答案**。每组问完，后面必须跟着一次真查。

| # | 问自己 | 查的方向 |
|---|---|---|
| 1 | 谁用、什么场景（手机／电脑、有没有网、给不懂的人用吗） | 平台限制、离线能力、适老化 |
| 2 | **上线前要办什么** | 软著／备案／资质／隐私政策／开发者账号 |
| 3 | 数据从哪来、丢了怎么办 | 存储与备份、删除与恢复、数据出境 |
| 4 | 钱怎么收、跑飞了怎么办 | 收款资质、费率、额度上限 |
| 5 | 出事了怎么办 | 日志与告警、客服渠道、回滚方式 |
| 6 | 以后加东西会不会堵死 | 现在省事的选择在半年后会不会变坑 |

## 7. 推演结果怎么写进方案（格式＋两栏）

> 原则：**每条要么带来源和日期，要么标"未查证"**；办不了的写"找谁问"，不许含糊。

```
### 上线前要办的事（人工活 —— 不用写代码，但要人去办）
| 事项 | 要求（查证于 YYYY-MM-DD） | 谁办 | 大概多久 | 查到的费用 | 卡住哪一步 |
|---|---|---|---|---|---|
| 软著 | 各应用市场基本都要（来源：xxx，2026-10-19） | 我 | 1–2 个月 | 官方免费，加急另算 | 上架 |
| 微信商户号 | 需营业执照（来源：xxx，2026-10-19） | 我 | 1–2 周 | 免费 | 收钱 |
| ⚠️ 隐私政策 | 收集任何信息就必须有（来源：xxx） | 他写/我代拟 | 1 天 | 0 | 上架 |

### 还没查清的（**未查证**）
- 应用市场对"AI 生成内容"的额外要求 —— 我查到的两篇口径不一致，**要问平台客服**。
- 这个事项**挡住**"上架"这一步；不影响先做核心功能。
```

**三栏分法（写死）**：

| 栏 | 判据 | 去哪 |
|---|---|---|
| **代码活** | 写代码能解决的 | 进"先做哪块"→ 以后进任务卡 |
| **AI 可执行前置** | 安装/下载/配置/建账号，AI 能跑命令完成的 | 写命令/验证/回退；大脑自己跑，或切一张“安装卡”给子 agent |
| **人工活** | **只有人能办**：办证/开户/付款/等审核/手机验证码/UAC 点按 | 上面那张表；**不进任务卡**（UAC 那一下单独标“人工点按”） |

> **安装先问一句“你自己来还是 AI 来”**；默认 AI 先试。**UAC/Store 登录**那一下 AI 点不了，只能用户点一下，但不要因此把整个安装写成“请你安装”。
