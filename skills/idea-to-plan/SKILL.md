# 想法 → 策划方案（0 编程基础也能用）

**一句话**：你不是在填表，你在**听他把话说完**，然后替他把"我想要个……"写成"他自己能拍板、大脑能接着聊"的产品底稿。

> **用户说得出 10%，剩下 90% 由系统问出来；问不完不交，但"结束"由用户宣布，不由 AI 宣布。**

> **先把分工说清楚**（这条决定了整份 skill 的写法）：
>
> - 你出的是**策划方案**：产品要什么、给谁用、用起来什么样、怎么算成、什么不能做。
> - 大脑拿方案后，会**和用户再聊几轮**，然后**自己出蓝图、契约、任务卡**，再派活执行。
> - 所以方案**不写**契约（CONTRACT）、字典（DICT）、蓝图（PROJECT_BLUEPRINT）、任务卡（TASKS）、模块/文件清单——那些是大脑的活。
> - **技术栈归方案**（用户 2026-10-22 拍板）：§8 给**结论 + 理由 + 换掉的代价**；依据是 7 个约束问题（在哪儿跑/几个人用/要不要联网/数据放哪/机器上有什么/谁维护/最怕什么）。仓库已有技术栈时以仓库为准，结论标「建议」。
>
> 方案的目标不是"一次切完、再也不问"，而是：**让大脑那几轮问得少一点、问得准一点，不拿技术问题去烦 0 基础用户。**
>
> 两层文档：
> **第一层（§0 一页结论）** 给用户看，全白话，他只需要看这一页；
> **第二层（§1–§13 产品规格）** 给大脑当对话底稿，精确到功能、场景、数据概念、验收、边界。
> 用户不需要看懂第二层；他只需要能说"这里不对/行/你定"。

## 一、什么是"好"（三条，按重要性排）

1. **他能拍板** —— **第一页**有他能看懂的一句话结论；技术细节不用他管，他只需要说"行 / 不行 / 这里不对"。**不要求他学编程，也不要求他懂术语。**
2. **大脑能少问几轮、问对问题** —— 目标、范围、功能行为、数据概念、验收、边界、前置（AI/你）、待问清单都够；大脑拿它聊几轮，**更容易**出蓝图/契约，不用从零问"你想要什么"。判据见 §八。
3. **不编** —— 外部事实带来源和日期；我替他定的标「🟡默认，可改」；真不知道的进「待问清单」标「⏳要你定」＋写默认做法＋影响。**没有第四种。**

> **标记口径（写进方案的每一个决定都要说清是谁定的）**：
> `✅已定`＝他确认过（用户原话 / 用户确认（时间））｜`🟡默认，可改`＝我定的（他授权）｜`⏳要你定`＝必须他点头，进 §12.1｜`🔍查证`＝外部事实带来源＋日期｜`⚠️红线`。
> ⛔ **方案正文不许出现"待定 / 后续补充 / 由执行方判断"这类字样**（自查第 18 条：待定词 = 0）——真不知道就写默认做法＋影响，或进【本期不做】。

> **权重纪律**：他主动说起"最担心什么"才接；**不要专门问**。"花多少钱"不问。
> 钱只在两种地方出现：① 查到的人工前置**实际费用**（带来源和日期）；② 他主动问起时，我按查到的事实回答。
> **不要**把"你希望花多少""预算多少"做成问题或选项。

## 二、五条铁律（违反任何一条＝这次失败）

| # | 铁律 | 怎么判 |
|---|---|---|
| 1 | **先听，再说** | 第一轮**不提问、不给选项**；先让他把想法倒完。他说 300 字和说 3 个字都行。 |
| 2 | **一次只补一个缺口** | 只问"答了会改变做法"的问题；能自己查／自己定的不问。**一次只问一个**，等他答完再下一个。 |
| 3 | **选项是扶手，不是门槛** | 最多 3 个候选，每个 ≤1 行；**永远允许直接打字**。不设"以上都不是，我说我的"这种元选项。 |
| 4 | **不问钱、不问技术** | 不把"预算多少""用什么框架"当问题。技术选型是大脑的活；产品形态（手机/网页/电脑/几个人用）可以问。钱按查到的事实说。 |
| 5 | **不编** | 外部事实：来源＋日期，或标「未查证」；我的决定：标「🟡默认，可改」；真不知道：进待问清单标「⏳要你定」＋默认做法＋影响。 |

**为什么第 3 条要写死**：选项是给"他说不出来"的人用的扶手，不是给所有人的必经流程。**用户想直接说，就让他说；他选了选项，也只当一句原话，不要把他锁在选项里。**

## 三、对话节奏（用户说、我补盲、缺口清单清零）

**三拍，循环到缺口清单清零为止**（**不设问数上限** —— 缺口由公式算出，产品大 ⇒ 格子多 ⇒ 问题自然多，"100 问也值得"）：

1. **听** —— "你先说，想到哪说到哪。不用整理，也不用挑选项。"
2. **复述 + 补盲清单** —— 先用他的话复述 5 行；再列**他没提到但我判断会影响成败的点**（≥5 条，每条一句人话）。
3. **逐条过缺口** —— 按缺口清单一条条问，**一次一个**；每条落在三种状态之一：**已答**（引用他原话 / 我定的默认）/ **本期不做**（写进矩阵格）/ **未答**。

### 3.1 缺口由公式算，写进方案（不许我少列）

```
缺口 = 主干 4 ＋ 形态约束 6 ＋ 技术栈 1
      ＋ 主线段数 × 3（观察/取/判）
      ＋ 元素数 × 维度数
      ＋ 底座 6
```

- 产品大 ⇒ 元素多 ⇒ 格子多 ⇒ **问题自然多**；
- **我只能填，不能删**：少列一条，方案里那行数字就对不上，用户一眼看得出；
- **范围可分批，维度不可分批**：W1 再小，6 条底座也得走完；
- 方案里必须写三行（格式固定，脚本按它解析；模板：`assets\元素清单.md`）：

  ```
  缺口 = 主干 4 ＋ 形态约束 6 ＋ 技术栈 1 ＋ 主线段数 × 3 ＋ 元素数 × 维度数 ＋ 底座 6
  = 4 + 6 + 1 + 3×3 + 4×8 + 6 = 58 项
  本次共 58 项，已答 52，本期不做 6，未答 0
  ```

- **未答 ≠ 0 ⇒ 不许交付**（验收就看这个数字；矩阵格数必须等于公式里的元素数×维度数）。

### 3.2 问题分三档（"带建议"的正确形态）

| 档 | 问什么 | 带不带建议 | 为什么 |
|---|---|---|---|
| **① 事实类** | 你现在怎么干的／最烦哪步／谁用／在哪用 | **不带**（空手听） | 要原话；给建议会被我带走（锚定） |
| **② 决策类**（占 90%） | 删了能不能找回／要不要多人／先做哪块 | **必带**：建议＋理由＋2 备选＋**各自代价** | 他没有判断依据，给结构才能做判断题 |
| **③ 契约类** | 主干／红线／本期不做 | **给候选让他挑**，但他必须**自己说一遍** | 只能他定；点头不算 |

**② 档四条硬规矩**：标注「我建议」不许伪装成他的想法 · 必须附代价 · 必须给反例 · 永远允许直接打字。
> 每一问的完整说法（档位 / 建议 / 理由 / 备选 / 代价 五列）见 `references\提问话术.md`，别在本文件里另写一套。

### 3.3 引导（0 基础专用）

| 招 | 做法 |
|---|---|
| **问后果，不问功能** | ❌"要不要数据备份" ✅"手机丢了，你的账还在吗" |
| **零件清单让他勾** | 给"这类东西通常有这些零件"的清单，他挑，不靠他想 |
| **反面案例** | "有个类似的东西因为没做 X，结果 Y" |
| **必须问一次** | 每个缺口至少问一次；他说"你定"才允许默认，并记"他授权" |
| **二选一** | 能做成选择题的，绝不做填空题 |

**三个禁令**：不问技术栈、不问预算、不用公文腔。

### 3.4 防"假点头"（100 问的真代价不是累，是敷衍）

| 招 | 做法 |
|---|---|
| **每问带理由** | "为什么问这件事"——理解了才会认真答 |
| **抽查 3 条** | 交付前随机抽 3 条问"这条是干嘛的"；**答不上 ⇒ 回去重问那条** |
| **契约类必须复述** | 主干/红线/不做，三处不许点头了事 |

**方向类问题必须三选一**（不许开放式）：

```
【问题】<一句话，不用技术词>

A. <选项> —— 理由：<跟他的处境挂钩>
B. <选项> —— 理由：……
C. <选项> —— 理由：……

👉 我推荐 A，因为 <指着他刚说过的话>
   三个都不合适？说说你的想法。
```

**他说了自己的想法之后（不照单全收）**：复述 → 过硬不硬（做得到吗）→ 再给三个选项（原样 / 原样+补盲点 / 更省的替代；做不到如实写原因）→ 继续循环。
**同一问题最多循环 3 次**；第 3 次还不定 ⇒ 给「默认方案 + 我不同意的地方」，他一句话拍板。
**留痕**：他说"就按我的，别劝了" ⇒ 记「用户拍板，我保留意见」+ 我当时担心的理由，写进方案风险栏。

> 轮子扫描、现场推演、自检在对话之后做，不占对话拍。
> 任何一拍他都可以说 **"别问了，你定"** —— 按默认定、标出来、继续走。
> 任何一拍他都可以**打断、补充、推翻**；以他最后说的为准。

## 四、流程：六段树（一条主干，先纵后横）

```
初始意图（他怎么说都行）
   │  ← 事实类：空手听，不给选项（防锚定）
   ▼
主干：给谁 ＋ 什么场景 ＋ 解决什么 ＋ 产出什么
   │  ← 闸①：用户用自己的话说一遍（不许只点头）
   ▼
形态与约束：在哪跑 / 几个人 / 联不联网 / 数据敏感 / 谁维护 / 最怕什么
   │  ← 决策类：必带建议＋理由＋2 备选＋各自代价
   ▼
技术栈：结论 ＋ 理由 ＋ 换掉的代价     ← 由「约束」推，**不由「品类」推**
   │
   ▼
纵向：一条主线走通（打开 → 用 → 拿到结果），每段写「观察什么/怎么取/判什么算成」
   │  ← 闸②：一段都不许是"大概是"
   ▼
元素清单：主线里出现的名词（界面 / 数据 / 规则 / 呈现 / 流程）
   │
   ├─ 横向 A 兜底：6 条底座，全走
   └─ 横向 B 长肉：元素 × 维度 矩阵，逐格（问过 / 本期不做）
   │  ← 闸③：矩阵空格必须标"本期不做"，表要写进方案
   ▼
交付：原话回述 ＋ 抽查 3 条 ＋ 问一句「要不要 PRD.html」
```

> **技术栈为什么不能从品类推**：同一个"记账工具"——自己用 → 一个脚本＋一个文件；手机用且要同步 → 网页＋云；店里三人用 → 桌面＋局域网。**产品一样，栈完全不同。**

**六段的顺序不许乱**：先纵向（一条线走通）再横向（逐元素查维度）——反过来会做出一堆"都有点用、连不成一条线"的功能。每段怎么做见 §五。

## 四附、三个闸（**人工 ＋ 可见**，不用脚本判）

> 理由（用户 2026-10-23）：skill 是对话，**产品定下来之前没有文档可扫**，闸只能靠人和可见性。

| 闸 | 谁判 | 怎么判 | 留下什么 |
|---|---|---|---|
| **① 主干** | **用户** | 他用自己的话说一遍"我要做的是……"，我核是否一致 | 方案里记：时间 ＋ 原话 |
| **② 纵向** | **我自查 ＋ 用户走查** | 主线每段写三段式；交付时让用户走「第一次用／日常／出错」，答不上就是缺 | 三段式直接写在方案里 |
| **③ 横向** | **我做 ＋ 用户看** | 元素×维度矩阵**写进方案**，空格标"本期不做" | 矩阵表 |

**"可见"替代"可验"**：方案里必须写一行 `本次共 N 项，已答 A，本期不做 B，未答 C`——**用户看得见数字和空格，就能拦。**

**方案体检脚本（`scripts\方案体检.mjs`）保留，但降级成"交付前自查报告"，不叫闸、不拦人。**

### 「不宣布结束」话术（固定，别自由发挥）

> 我不能替你说"好了"。**缺口没清零我就不许收尾**（现在：共 N 项，未答 C 项）。
> 你可以说 **"就这样，别问了，按默认定"** —— 那是**你宣布结束**，我把剩下的一律按默认填、标「🟡默认，可改」，然后才交付。
> 也可以下次接着聊；这份方案留在原地，不清零不交。

## 五、每一段怎么做

### 段① · 事实（**这一轮不要提问**）

开口只说这一段（或它的自然变体）：

> **你先说：你想做个什么东西、给谁用、现在这件事你怎么干的、你最烦哪一步。**
> 想到哪说到哪，不用按顺序，也不用挑选项。说完我会复述给你听。

> ⚠️ 这四句是**提示**，不是四个问题：**不要逐条问**，等他说完再复述。铁律 1 说的是"第一轮不提问"。

**这一轮禁止做的事**：
- 不要弹 A/B/C/D；
- 不要问"你的预算是多少"；
- 不要问"用 React 还是 Vue"；
- 不要急着给方案；
- 不要用"请提供需求"这种公文腔。

**他说的过程中**：只记，不打断，不纠正。除非他明显停下来等你回应，才用一句"嗯，然后呢？"接住；**不要连着问第二个**。

### 段② · 主干（复述 → 闸① → 补主干缺口）

**复述模板**（用他的话，不用我的话）：

> 我听到的是：
> 1. 你想做的是：……
> 2. 给谁用：……
> 3. 现在你是这么干的：……
> 4. 你最烦的是：……
> 5. 你希望用起来是这样：……
>
> **有没有说错、漏了、或者我理解偏了？**

**他没说到的行，写"还没说"，不要替他编。**
**合格**：他会说"对，就是这个"或者"不对，应该是……"。
**不合格**：你复述了一堆术语，他只能说"差不多吧"。

**闸①**：复述之后请他**用自己的话说一遍**"我要做的是……"；只点头不算过。原话和时间记进方案。

**主干 4 个缺口**（缺口公式的头 4 项）：给谁／什么场景／解决什么／产出什么。一次一个，话术见 `references\提问话术.md`（每问带档位/建议/理由/备选/代价）。

### 段③ · 形态与约束（6 个）

在哪跑 / 几个人用 / 联不联网 / 数据敏感不敏感 / 谁维护 / 最怕什么。**这是决策类** ⇒ 每问必带建议＋理由＋2 备选＋各自代价。
他只说"行 / 换一个"即可；说不清就按默认走。产品约束小表（形态／谁用几个人／内网还是公网／要不要离线／数据敏感度／规模）见 `references\产品形态与约束.md`。
**产品形态**在他说的话里已经清楚就不再问；没说清才问一个："这东西是装在手机里、在电脑上打开网页、还是只在你自己电脑上跑？"

### 段④ · 技术栈（由约束推，不由品类推）

按 7 个约束问题（在哪儿跑/几个人用/要不要联网/数据放哪/机器上有什么/谁维护/最怕什么）推出：
**结论 ＋ 理由 ＋ 换掉的代价**，写进 §8.2；仓库已有技术栈 ⇒ 以仓库为准，结论标「建议」。
⛔ **不问用户技术问题**；⛔ 不给一堆候选让用户选。

### 段⑤ · 纵向（一条主线走通；闸②）

把主线切成段（打开 → 用 → 拿到结果），**每段写三段式**：

```
观察什么：<具体的东西>
怎么取：  <一条命令 / 一个路径 / 一个操作步骤>
判什么算成：<阈值，或"出现什么字样"，或"数值在什么范围">
```

- 细节、引导四步、说不清怎么办 → §七附「三关」；
- **闸②**：一段都不许是"大概是"；交付时让用户走「第一次用／日常／出错」三条，答不上就是缺。

### 段⑥ · 横向（元素清单 → 底座 6 → 元素×维度矩阵；闸③）

1. **元素清单**：主线里出现的名词（**界面 / 数据 / 规则 / 呈现 / 流程**）。模板：`assets\元素清单.md`。
2. **底座 6 条（每个产品都必须走完）**

   | # | 维度 | 问的是 |
   |---|---|---|
   | 1 | **正常** | 顺利用完一遍，看到什么 |
   | 2 | **异常** | 用错了、输错了、点错了 |
   | 3 | **边界** | 没有数据／数据很多／极长／极值 |
   | 4 | **共享** | 还有谁在用；同时用会怎样 |
   | 5 | **规模** | 数据变多会不会变慢、变乱 |
   | 6 | **失败与恢复** | 崩了、断了、丢了，怎么回来 |

3. **专用维度（由元素触发，0–8 条不定）**

   | 专用维度 | 什么元素出现才挂 | 典型问题 |
   |---|---|---|
   | 权限与可见性 | 有"人"（多人／对外） | 谁能看、谁能改、谁能删 |
   | 一致性与对账 | 有"钱/库存/名额/次数" | 扣了没到账、重复提交、超卖 |
   | 时序与顺序 | 有"消息/回合/流程" | 乱序、重复、断线重连 |
   | 多端同步 | 有"多设备" | 手机改了，电脑何时看到 |
   | 隐私与合规 | 有"个人信息" | 能不能导出、要不要同意、删号怎么删 |
   | 内容合规 | 有"用户上传/公开内容" | 要不要审、违规怎么处理 |
   | 可访问性 | 有"公开给很多人" | 小屏、老人、没鼠标 |
   | 可观测 | 有"要长期维护" | 出问题怎么查、谁改的 |

   **为什么专用维度不进底座**：单人小脚本不需要"内容合规"，单机小工具不需要"多端同步"。全上 14 条 = 问题翻倍且大半是废话。
   ⛔ **元素触发，不按品类触发**：不许因为"这是游戏/这是网站"就加维度或模板——只看元素本身。

4. **元素×维度矩阵写进方案**：逐格标「问过 / 本期不做」，**空格不许留**（闸③）。模板：`assets\元素清单.md`；"不做"的语义与写法：`assets\本期不做.md`。
5. **现场推演外部依赖（去查，不查表）** —— 见本节末"现场推演"。

### 交付 · 写方案（两层一份文件）＋ 自查 ＋ 收尾

1. **写方案**：按 `assets\施工级模板.md` 写。**不要问"你要 PRD 还是一页版"** —— 这份文档第一页就是给他看的一页结论，后面是给大脑当对话底稿的产品规格。小工具可以把后面几节写短，但**不能省掉验收和红线**。
2. **产物形态**：策划文档 `.md`（永远）／施工文档（一份装不下或产品够大时拆多份，按模块）／**PRD.html**（**末尾问一句要不要**；不要就只给 `.md`，模板 `assets\PRD.html`）。**每条承诺标来源**（见 §一 的标记口径）：`用户原话` / `用户确认（时间）` / `我定的默认（他授权）` —— 说不清是谁说的，就等于没定。
3. **写的时候守四条**：
   1. **先写 §0 一页结论，给他看**；他点头/改完，再补 §1–§13。
   2. **每条功能都要有"怎么算做成了"**；写不出就说明还没想清楚，回段②补一句。
   3. **产品事实我写，技术选型我只写结论**：他确认过的标「✅已定」；我替他定的标「🟡默认，可改」；必须他拍板的标「⏳要你定」进 §12.1，**同时**写默认做法＋影响（正文不许留"待定"字样）。
   4. **§12 必须列"大脑可能会问的"**：每条给默认值和影响。**这是判断（还没试点数据）**：我们预期它比多写两页技术细节更能减少来回；依据见 `references\依据.md` §5。
4. **交付前自查**：逐条过 §八（`references\方案体检.md`）；需要问他时**最多补 1 问**。缺口数字没清零、矩阵有空格、有待定词 ⇒ **不许交付**。
5. **抽查 3 条**（防假点头）：随机抽 3 条问"这条是干嘛的"；答不上 ⇒ **回去重问那条**。
6. **收尾**：定项目文件夹（`{{项目根}}\<拼音>\`，**只建这一个文件夹，不要在里面造 `.obsidian\`** —— 用户 2026-10-24：\"没有用\"）→ 写 `策划方案.md` → 建调研库（**只有真查过资料才建**）→ `项目管理.md` → §13 交接块 → 按 §十二 给交付三件套。

### 现场推演（外部依赖，**去查，不是查表**；顺便问"谁装"）

> ⚠️ 资质／备案／平台要求／费率这些东西**一年一变**。把答案写死在 skill 里，等于教人按去年的话办事。

1. **抠点**：逐句过他的方案，凡是"不能靠写代码搞定"的都是外部依赖点。
   例：`做成手机 App` → 应用市场／软著／隐私政策／开发者账号；`要收钱` → 收款资质；`用 AI` → key 与额度；`上网上` → 域名／备案；`发短信` → 签名与模板报备。
2. **每个点查清 5 件**：现在的要求（不是去年的）／谁办／大概多久／**查到的费用**／最近变过没。
3. **查的纪律**：权威源优先；至少两个独立来源对上才算查到；**每条记 URL ＋ 抓取日期**。
4. **查不到**：换词再查 → 查"该找谁问" → 标「未查证」并写清**它挡住哪一步**。
   ⛔ **不许凭印象写"大概 30 天""应该免费"**。
5. **落库**：按场景建抽屉，原文进 `资料/`，来源走 `登记来源.mjs`；下次同类问题一查就有。
6. **产出分三栏，不是两栏**：
   - **代码活**：写代码能解决的 → 进方案「先做哪块」→ 以后进任务卡。
   - **AI 可执行的前置**（安装/下载/配置/建账号）：**先问一句"这个安装你自己来，还是 AI 来？"**（有 `ask_user_question` 就弹二选一；没有就文字问）。默认 **AI 先试**；写清命令/验证/回退；大脑可以自己跑，也可以派子 agent。**不要默认写成人工前置。**
   - **人工活**：**只有人能办**的（办证/开户/付款/等审核/手机验证）→ 单列，写谁办／多久／查到的费用／卡住哪一步，**不进任务卡**。

> ⚠️ **UAC / Microsoft Store 登录 / 手机验证码**这种系统弹窗，AI 点不了，只能用户点一下。**但这不等于整个安装都归人工**：方案要写"AI 装，弹窗时你点一下"，而不是"请你安装"。

> 方法见 `references\现场推演与调研.md`。

## 六、参照系（先给"好"找一个标尺）

**规矩：每条"好"的承诺，都必须能指向一个参照源**——不然做出来就是"我觉得还行"。

| 级 | 来源 | 什么时候用 | 取什么 |
|---|---|---|---|
| **S1** | 对标物原始规格 | 有明确参照（复刻、仿制） | 帧率、常量、尺寸、动画帧数、节奏 |
| **S2** | 同类产品通用规格 | 有品类、无唯一参照 | 行业通用做法（列出 2–3 家对比） |
| **S3** | **平台与工程基线（永远有）** | **任何项目** | 响应<100ms、启动<3s、保存不丢、崩溃可恢复、误操作可撤销、1000 条不卡 |
| **S4** | 用户现在的做法 | 无产品可比、但有现状 | "现在手动 20 分钟 ⇒ 目标 ≤2 分钟" |
| **S5** | 探索（只判可达） | 全新品类 | 只判"1 分钟内能否完成第一次核心动作" |

**三条纪律**：
1. **至少两源一致**才写成硬指标；只有开源复刻一源 ⇒ 标「待核」。
2. 优先级：原版规格 > 权威分析 > 逐帧测量 > 开源复刻（复刻只做交叉验证）。
3. 问不到用户的，就用 S3 兜底（工程基线永远可以引）。

**现代化默认**（"复刻一个旧东西"时必问）：先查原版**真实**帧率（别想当然）；换算**先转成每秒**再除以目标帧率（防速度翻倍）；输入延迟 ≤1 帧；分辨率按整数倍放大。

> 参照系写进方案 §1，**不单独成文**。

## 七、方案必须有什么（产品规格 10 项：**主干 2 ／ 纵向 2 ／ 横向 6**）

> 这 10 项就是"够不够详细"的判据。**缺一项，大脑就得多问一轮；不是"必须一次切完"。**
> 契约/蓝图/任务卡**不在**这 10 项里——那是大脑聊完以后自己出的。

**主干（2 项）—— 决定"做什么、给谁"**

| # | 必须有什么 | 写到什么程度 | 为什么大脑需要它 |
|---|---|---|---|
| 1 | **一句话目标 ＋ 这一版不做什么** | 一句人话；不做什么至少 3 条 | 决定聊天的起点和范围 |
| 2 | **谁用、什么场景** | 角色 ＋ 3 个端到端场景（第一次用／日常／出错） | 决定问什么、角色/权限怎么定 |

**纵向（2 项）—— 一条主线走通，每段能验**

| # | 必须有什么 | 写到什么程度 | 为什么大脑需要它 |
|---|---|---|---|
| 3 | **功能清单 F1..Fn** | 每个功能：谁、什么时候、做什么、看到什么、没有数据怎么办、出错怎么办、不做什么 | 决定卡怎么切 |
| 8 | **验收 AC** | 每个 F 至少 1 条：给定／当／应该／具体例子／什么算失败／怎么验证 | 大脑聊完出卡时翻成验收命令 |

**横向（6 项）—— 元素逐格查维度，边界清清楚楚**

| # | 必须有什么 | 写到什么程度 | 为什么大脑需要它 |
|---|---|---|---|
| 4 | **产品数据概念** | 名词表、数据对象、关键字段、状态、权限、删除/保留/备份、当天口径、老数据、账号来源；**概念级**，不写类型/表/接口 | 帮大脑问对数据问题 |
| 5 | **界面与状态** | 页面/入口、空/加载/出错、关键文案 | 决定验收和前端卡 |
| 6 | **外部依赖与谁办** | 查到的要求＋来源＋日期；**每条写谁办：AI／你**；AI 可执行前置写命令/验证/回退；只有人能办的才进"人工前置"；未查证的写清挡哪一步 | 决定哪些进卡、哪些不进卡 |
| 7 | **产品形态与约束（＋路线）** | 手机/网页/电脑/小程序/脚本；单机/多人；内网/公网；离线/在线；数据敏感度；规模；§8.1 记现成方案/自写 | 大脑据此定技术栈和轨道 |
| 9 | **红线与不做** | 至少 3 条具体的"绝对不能" | 决定卡的边界/白名单 |
| 10 | **分批 W1..** | 每批做完能看到什么；W1 是最窄的完整切片 | 决定波次和先做哪块 |

> **详细的模板**见 `assets\施工级模板.md`；横向的元素清单/矩阵/缺口数字用 `assets\元素清单.md`，"本期不做"用 `assets\本期不做.md`。**不要**把"功能清单"写成"记账功能、统计功能、导出功能"这种标签；要写成"谁在什么情况下做什么、看到什么"。
> 不确定"写到什么程度算够"？看 `assets\示例-小店记账.md` —— 一份填好的成品，结构体检通过。

## 七附、「三关」——每条承诺都要能验（适用于所有产品）

> 为什么单开一节：方案里最贵的错不是"写少了"，是**写了一条永远验不了的承诺** ——
> 执行方到那一步才发现"没法验"，于是要么瞎验收、要么回来问，两头都烧时间。

### 不分类，只问两个问题

**不要**先判断"这是游戏 / 工具 / 网站"再套模板 —— 分类本身就是一次判定，遇到没见过的类型就漏了。
对**每一条承诺**（不是每个产品）只追问两句：

```
问题 1：这条承诺「成了」的时候，什么会变？
        （一个能看见 / 能读到 / 能测到的东西）
问题 2：那个东西从哪拿？
        （命令 / 文件路径 / 界面上的位置 / 一段指标）
```

答案必须落成**三段式**（这三行就是验收条款的正文）：

```
观察什么：<具体的东西>
怎么取：  <一条命令 / 一个路径 / 一个操作步骤>
判什么算成：<阈值，或"出现什么字样"，或"数值在什么范围">
```

**长这样（是例子，不是分类）**

| 承诺 | 观察什么 | 怎么取 | 判什么算成 |
|---|---|---|---|
| 角色能攻击 | 画面里出现攻击动作 | 录 15 秒，抽 3 帧 | 第 2–3 帧有明显位移 |
| 能记账并保存 | 一条账目在文件里 | 打开 `data/ledger.json` | 有那条记录且金额正确 |
| 接口能用 | 一次请求的响应 | `curl -s .../api/x` | HTTP 200 且 `ok:true` |
| 启动不卡 | 从点击到窗口出现 | 秒表 / 脚本计时 | < 3 秒 |

### 说不出「什么会变」怎么办 —— 不许甩锅，要引导出来

用户本来就说不出"证据形态"，**所以不能把问题原样抛回去，更不能留给无人值守去猜**。
**引导四步（按顺序做，不许跳）**：

| 步 | 做什么 | 为什么有效 |
|---|---|---|
| ① **给例子** | "别人做类似的东西，是这样验的：……"（给 2 个具体的） | 用户不会从零描述，但会挑 |
| ② **请他演一遍** | "如果你现在要试这一条，你会怎么试？"（让他描述动作，不要术语） | 用户能说"我点一下、看看出不出数字"，这就够了 |
| ③ **给 2–3 个候选让他选** | "那验收就看：A 屏幕上出现结果 / B 文件里有记录 / C 别人打开也能用 —— 哪个算成？" | 选择比开放问题简单一个数量级 |
| ④ **AI 负责翻译** | 把他选的那个，翻译成「观察什么 / 怎么取 / 判什么算成」 | 翻译是 AI 的活，不是用户的活 |

只有四步都做完仍然说不清（极少数）才可以：**把承诺拆小**（拆到能说清怎么验），或标【本期不做】并写明"缺什么才能验"。
**⛔ 绝不允许留空交给下游**：方案里出现"待定 / 后续补充 / 由执行方判断"这类字样，视为**方案不合格**。

> **验收的判据不是"写出来了"，是"用户点头了"**：三段式必须在对话里被确认过（"对，这样就算成了"）才能进方案。

### 为什么这样就不会漏类型

任何产品，只要它"成了"，一定有某个东西会变 —— 画面、文件、输出、响应、数值。
我们问的是"**变的是什么**"，不是"**你属于哪一类**"；遇到没见过的东西，它照样能回答这两句。

### 三条硬规则

1. **写不出三段式 ⇒ 先走「引导四步」问出来**；四步走完仍不行才拆小或标【本期不做】，**不许留空给下游**；
2. **证据必须"能取"**：写清命令 / 路径 / 位置，**禁止**"看起来没问题""测试通过"；
3. **给人看的那版不出现 E1 / E2 / E3 术语**：每条功能下只写一句人话 —— "**怎么算成了**"。

### 两层输出（配合无人值守）

| 层 | 给谁 | 内容 |
|---|---|---|
| **人话版** | 用户 | 功能清单 ＋ 每条一句"怎么算成了" |
| **执行版** | 大脑 / 无人值守 | 三关表（观察什么 / 怎么取 / 判什么算成）＋ 契约编号 |

**不做**：不把"三关"变成新的术语墙（用户只看人话版）；不要求 0 基础用户选技术栈（技术栈仍由 AI 给结论，见段④）。

### 输出形态

| 产物 | 条件 | 格式 |
|---|---|---|
| **策划文档**（主） | 永远 | `.md` |
| **施工文档** | 一份装不下 / 产品够大 | `.md`，**可多份**（按模块分） |
| **PRD.html** | **末尾问一句**；不要就只给 `.md` | 单文件、零依赖（模板 `assets\PRD.html`） |

**每条承诺必须标来源**：`用户原话` / `用户确认（时间）` / `我定的默认（他授权）` —— **说不清是谁说的，就等于没定。**

## 八、交付前自查（15 条人判 ＋ 3 条数字/表格项；**报告不拦人，数字不平不许交付**）

> 逐条过 `references\方案体检.md`；`scripts\方案体检.mjs` 出的是**自查报告**（不叫闸、不拦人）。
> **缺什么补什么**；需要问他时，**最多补 1 问**，不要重新来一轮问卷。
>
> ```
> node "<本 skill 目录>\scripts\方案体检.mjs" --file "<方案路径>"
> ```
>
> 报告点名的项要补齐或降级；**结构过 ≠ 内容合格**，15 条人判仍要自己过。

**三条数字/表格项（对不上 ⇒ 不许交付）**：

| # | 自查 | 判据 |
|---|---|---|
| 16 | **缺口数字** | 三行齐：公式行 / 计算行 / `本次共 N 项，已答 A，本期不做 B，未答 C`；N=A+B+C；计算行总数=N；**未答 C=0**；公式里的元素数×维度数 = 矩阵实际格数 |
| 17 | **矩阵空格** | 元素×维度矩阵每格都标了「问过 / 本期不做」，没有空格 |
| 18 | **待定词 = 0** | 全文没有"待定 / 后续补充 / 由执行方判断"这类甩锅词；AC 里没有"流畅/美观/良好/合理/稳定/好用"这种不可机判词 |

**15 条人判**（详细判据、例子和"三档结论"见 `references\方案体检.md`）：

| # | 自检 | 不过就补什么 |
|---|---|---|
| 1 | 一句话目标能用**一句人话**说完？ | 说不完 ⇒ 回段②复述 |
| 2 | **这一版不做什么**至少 3 条？ | 没有 ⇒ 我提 3 条让他点头 |
| 3 | 每个 **F** 都有"谁/什么时候/做什么/看到什么"？ | 缺 ⇒ 补功能规格 |
| 4 | 每个 **F** 都有至少 1 条 **AC**，且 AC 有具体例子？ | 缺 ⇒ 追一句"给个具体例子" |
| 5 | 每条 AC 都有"什么算失败"？ | 没有 ⇒ 我替他写反例，让他确认 |
| 6 | **数据对象/字段/状态/权限/当天口径/老数据/账号**说得清？ | 说不清 ⇒ 写默认做法＋影响，或进【本期不做】 |
| 7 | **权限/谁能看什么**说得清？ | 说不清 ⇒ 按"只有他自己用"先定，标默认 |
| 8 | **外部依赖**都查过，或标了「未查证」＋挡住哪一步？每条写谁办（AI/你）？AI 装的有命令/验证/回退？ | 没查 ⇒ 去查；查不到 ⇒ 标未查证；**能 AI 装的不许默认写"你装"** |
| 9 | **产品形态与约束（＋路线）**说得清？**§8.2 技术栈**给了结论？ | 没有 ⇒ 按 `references\产品形态与约束.md` 补；路线见 §8.1 |
| 10 | **红线**至少 3 条，且具体？ | 没有 ⇒ 我提 3 条让他挑 |
| 11 | **W1** 是最窄的完整切片，做完能演示？ | 不是 ⇒ 重切 |
| 12 | 方案摘要 ＋ F/AC 索引 ＋ **"大脑可能会问的"**清单齐？没有占位符？ | 缺 ⇒ 补齐再交 |
| 13 | **每条 AC 都标了证据等级 E1/E2/E3**（E1 呈现／E2 内证／E3 人判），且标"能看到"的必须是 E1 或 E3？ | 缺 ⇒ 逐条标；拿不准的标 E3 |
| 14 | **§8 技术栈**给了结论 + 理由 + 换掉的代价，且结论是从 7 个约束问题推出来的？ | 缺 ⇒ 按段④补齐 |
| 15 | **每条承诺都有三段式**（观察什么 / 怎么取 / 判什么算成），且**用户在对话里点头过**？方案里**没有任何**"待定 / 后续补充 / 由执行方判断"？ | 缺 ⇒ 回 §七附 走「引导四步」问出来；四步不行就拆小或标【本期不做】 |

## 九、与「无人值守」的分工（**别替大脑干活**）

- **方案不出任务卡**。卡由「无人值守」的大脑拿到方案、和用户聊几轮后自己切（它要看真实代码库才能定文件清单）。
- **交付后大脑会再聊几轮**：这是正常的，不是方案没写好；方案的作用是让那几轮聊得少、问得准。
- **方案不出契约/蓝图**。`CONTRACT.md`、`DICT.md`、`PROJECT_BLUEPRINT.md` 都是大脑的产物；方案只提供产品事实和待问清单。
- **方案写「怎么取」，不写测试命令**：三段式里的「怎么取」（打开哪个文件、跑哪个动作、看哪）是**产品事实**，方案必须写清；**最终测试命令归大脑**（测试命令/门禁配置必须看仓库才能定，方案写了也是猜）。
- **方案不写模块/文件清单**（这些必须看仓库）；**技术栈要给结论**（§8，结论＋理由＋代价），仓库已有则以仓库为准。
- 方案能做的是：**让大脑那几轮聊得少、问得准**——目标/范围/功能行为/数据概念/AC/红线/前置（AI/你）/待问清单齐了，它就不用从零问"你想要什么"。
- **"方案够详细"不等于"零返工"**：方案减少的是"产品问题来回"；真正的零返工还靠契约冻结＋门禁＋审核，这三样在大脑那边，不在这份 skill 里。**不要把这句话省掉。**
- 详细分工（大脑怎么读、方案提供什么/不提供什么、摘要格式、"大脑可能会问的"清单）见 `references\无人值守对接.md` —— **这是给大脑看的，别讲给用户听**。
- 为什么这么设计、哪些有证据、哪些只是判断：见 `references\依据.md`。**别把"判断"说成"已证明"。**

## 十、什么时候**不用**这个 skill

1. 他已经有明确方案，只等执行 → 直接去派活。
2. 一次性的小改（一句话能说清）→ 直接干。
3. 只想要一份 README 或说明 → 普通文档，不是策划。
4. 他只是问一个技术问题 → 直接答。
5. 他只想聊方向、还没准备做 → 可以聊，但不要硬产出产品规格；先给一页判断。

## 十一、九个最常见的错法（0 基础场景）

| ❌ 错 | ✅ 对 |
|---|---|
| 一上来就弹 A/B/C/D，连弹十轮 | 先让他说；缺口按公式算、一次问一个；选项最多 3 个，永远允许直接说 |
| 用"以上都不是，我说我的"当第四选项 | 删掉这个选项；单独一行："不想选就打字说你的，不用选" |
| 问"你希望花多少钱" | 不问预算；只写查到的人工前置实际费用，或他主动问时按事实答 |
| 只写"记账功能、统计功能、导出功能" | 写"谁在什么情况下做什么、屏幕上看到什么、出错怎么办" |
| 把"好用/稳定/流畅"当验收 | 写"三笔账加起来等于 50.5；刷新后还是 50.5；导出文件里三行都在" |
| 把契约/蓝图/模块清单写进方案，替大脑干活 | 方案只写产品事实、约束和**技术栈结论**；契约/蓝图留给大脑 |
| **把 AI 能装的软件写成"请你安装"** | 策划时问一句"你装还是 AI 装"；默认 AI 先试，写清命令/验证/回退；只有 UAC/Store 登录那一下让用户点 |
| 用户答不上来就卡住 | 我替他排一个默认，标「🟡默认，可改」，请他否决 |
| 方案只有一页，就交给无人值守 | 一页只是 §0；后面必须有 §1–§13 产品规格，否则大脑还得从零问 |
| **交付消息只丢一句"方案写好了"** | 必须按 §十二 给三块：建了什么/在哪、去 DSH 添加工作区＋选无人值守、可直接粘的提示词 |
| 把项目建在 Obsidian 库里（`{{知识库}}\`） | 建在 `{{项目根}}\<拼音>`：路径纯 ASCII，代码和文档都在同一个文件夹里。**不要预先造 `.obsidian\`**（它是 Obsidian 打开库时自己生成的，我们造个空的没意义，用户 2026-10-24 拍掉） |

## 十二、交付时要说的话（**固定格式，不许省**）

方案落盘之后，**最后一条消息必须包含下面三块**，顺序别换、别合并。

### 1 建好了什么、在哪

一张表，让他照着找得到：

| 东西 | 位置 |
|---|---|
| **项目文件夹（全部东西都在这一个里）** | `{{项目根}}\<拼音>` |
| 策划方案 | `<项目文件夹>\策划方案.md` |
| 项目管理（这是什么／到哪了／下一步） | `<项目文件夹>\项目管理.md` |
| 调研库 | `<项目文件夹>\文档\调研\_索引.md`（N 个抽屉 / M 条来源） |
| 以后大脑生成的 | `<项目文件夹>\PROJECT_BLUEPRINT.md`、`TASKS.md`、`_crew\`、代码 |

没建调研库就写一行「本次没有前置调研，没建库」，**不要留空指针**。

### 2 你现在要做的三步（**必须写；用户不知道**）

> **① 想在 Obsidian 里看，就「打开本地仓库」选 `{{项目根}}\<拼音>`；不用 Obsidian 就跳过这步。**（`.obsidian` 是 Obsidian 打开库时**自己生成**的 —— skill 不预建、也不该建。）
> **② 在 DSH 里「添加工作区」，选 `{{项目根}}\<拼音>`。**
> **③ 然后选「无人值守」。**
> **④ （顺手）在这个库的「设置 → 文件与链接 → 排除的文件」里把代码目录排除掉**，否则以后全库搜索会被代码文件淹没。

漏了这几步，用户拿着方案不知道该往哪放——这是最容易断的地方。

### 3 一段可以直接粘进去的提示词

用代码块给出，**整段可复制**：

```
这个项目的策划方案已经写好了，按无人值守流程开始。

项目文件夹：{{项目根}}\<拼音>
方案：{{项目根}}\<拼音>\策划方案.md
项目管理：{{项目根}}\<拼音>\项目管理.md
调研库：{{项目根}}\<拼音>\文档\调研\_索引.md

规则：
1. 方案里标「🟡默认，可改」的，按默认做，不要问我。
2. 只有标「⏳要你定」的、和 §12.1 里"要现在定"的，才问我。
3. 先出蓝图和任务卡，先做 W1；W1 做完先给我看，别一口气往下跑。
4. 我不懂技术，别跟我说术语。
```

**纪律**：

- 提示词只放**指针 + 规则**，**不要把方案里的步骤抄一遍**——抄了会走样，而且越长越慢。
- 路径一律写**绝对路径**；不要写"上面那个文件"，大脑读不到指代。
- 没建调研库 ⇒ 删掉提示词里那一句括号，别留空指针。
- 这三块之后**不要再追加解释**：用户要的是能直接复制的东西。
